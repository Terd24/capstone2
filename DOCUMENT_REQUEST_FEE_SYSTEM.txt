✅ DOCUMENT REQUEST FEE SYSTEM - COMPLETE
==========================================

OVERVIEW:
--------
When a student requests a document, if the Owner has set a fee for that 
document type, a balance is automatically created in the Cashier system.
If the fee is ₱0, no balance is created.

NEW FILES CREATED:
-----------------
1. OwnerF/ManageDocumentFees.php
   - Backend API for managing document request fees
   - Fetches document types from document_types table
   - Stores fees in document_fees table
   - Handles GET (list fees) and POST (update fees)

2. includes/create_document_balance.php
   - Helper function to create balance when document is requested
   - Checks if document has a fee > 0
   - Creates entry in student_balances table
   - Links to Cashier system

DATABASE TABLES:
---------------
Table: document_fees
Columns:
  - id (INT, AUTO_INCREMENT, PRIMARY KEY)
  - document_name (VARCHAR(100), UNIQUE, NOT NULL)
  - fee_amount (DECIMAL(10,2), DEFAULT 0.00)
  - is_active (BOOLEAN, DEFAULT TRUE)
  - created_at (TIMESTAMP)
  - updated_at (TIMESTAMP)
  - INDEX on document_name
  - INDEX on is_active

Table: student_fee_items (existing, used by Cashier for storing fees)
  - id (INT, AUTO_INCREMENT, PRIMARY KEY)
  - id_number (student ID)
  - student_name
  - grade_level
  - school_year_term (e.g., "2025-2026 1st Semester")
  - fee_type (stores "Document Request Fee - [Document Name]")
  - amount (total fee amount)
  - paid (amount already paid, starts at 0)
  - date_added (timestamp)

HOW IT WORKS:
------------
1. OWNER SETS FEES:
   - Owner logs in to Dashboard
   - Clicks "Document Fees" in sidebar
   - Sees list of all requestable document types
   - Clicks "Edit Fee" for any document
   - Sets fee amount (₱0 or higher)
   - Saves

2. STUDENT REQUESTS DOCUMENT:
   - Student/Parent requests a document
   - Request status: "Pending"
   - No balance created yet

3. REGISTRAR APPROVES REQUEST:
   - Registrar changes status to "Approved"
   - System checks if document has a fee in document_fees table
   - If fee > ₱0:
     * Creates entry in student_fee_items table
     * Fee type: "Document Request Fee - [Document Name]"
     * Amount: Fee set by Owner
     * Paid: 0 (unpaid)
   - If fee = ₱0:
     * No balance created
     * Document request proceeds normally

4. CASHIER SEES BALANCE:
   - Balance appears in Cashier system immediately after approval
   - Student must pay before claiming document
   - Cashier can process payment normally

INTEGRATION POINTS:
------------------
1. Document Types (document_types table)
   - Source of truth for available documents
   - Only is_requestable=1 documents shown

2. Document Requests (document_requests table)
   - Triggers balance creation
   - Links document type to fee

3. Student Balances (student_balances table)
   - Stores the fee as a balance
   - Cashier uses this for payment processing

4. Cashier System
   - Sees balances automatically
   - Processes payments normally
   - No changes needed to Cashier code

1. Owner sets "Form 137" fee to ₱50.00
2. Student requests "Form 137" (Status: Pending)
3. Registrar reviews and approves request (Status: Approved)
4. System automatically creates balance:
   - Student: Juan Dela Cruz
   - Fee Type: "Document Request Fee - Form 137"
   - Amount: ₱50.00
   - Paid: ₱0.00

5. Cashier sees ₱50.00 balance for Juan
6. Student pays ₱50.00
7. Cashier marks as paid
8. Registrar marks as "Ready to Claim"
9. Student claims document (Status: Claimed)
