🔧 TROUBLESHOOTING: Balance Not Showing in Cashier
===================================================

QUICK DIAGNOSIS:
---------------
Run these 3 scripts in order to find the problem:

1. http://localhost/onecci/check_term_format.php
   → Shows what term format is being used

2. http://localhost/onecci/debug_document_balance.php
   → Shows complete system status

3. http://localhost/onecci/test_create_balance.php
   → Manually creates a balance to test

MOST LIKELY ISSUES:
------------------

ISSUE #1: Document name doesn't match exactly
----------------------------------------------
Problem: "Form137" in document_fees but "form137" in request
Solution: Check exact spelling and capitalization

To check:
SELECT document_name FROM document_fees WHERE is_active = 1;
SELECT DISTINCT document_type FROM document_requests;

They must match EXACTLY!

ISSUE #2: Status not exactly "Approved"
---------------------------------------
Problem: Status might be "approved" or "APPROVED" (wrong case)
Solution: Make sure it's exactly "Approved" with capital A

To check:
SELECT id, student_id, document_type, status 
FROM document_requests 
WHERE id = [your_request_id];

ISSUE #3: School year term mismatch
-----------------------------------
Problem: Balance created with different term than Cashier expects
Solution: Check term format

Run: check_term_format.php
Look for: What term Cashier is looking for vs what was created

ISSUE #4: Function not being called
-----------------------------------
Problem: update_document_status.php not calling createDocumentBalance()
Solution: Check PHP error log

Location: C:\xampp\php\logs\php_error_log

Look for:
"=== DOCUMENT APPROVED - CREATING BALANCE ==="
"=== CREATE DOCUMENT BALANCE START ==="

If you don't see these, the function isn't being called!

ISSUE #5: Database INSERT failing silently
------------------------------------------
Problem: Function runs but INSERT doesn't work
Solution: Check for SQL errors

Run test_create_balance.php and check Step 5
If it says "SUCCESS" but no balance found, there's a database issue

STEP-BY-STEP FIX:
----------------

STEP 1: Verify Document Fee is Set
----------------------------------
1. Login as Owner
2. Go to Document Fees
3. Check Form137 has a fee > ₱0
4. If not, set it now

STEP 2: Verify Document Request Exists
--------------------------------------
1. Run this SQL:
   SELECT * FROM document_requests 
   WHERE student_id = '02200000001' 
   AND document_type = 'Form137';

2. Note the 'id' and 'status'

STEP 3: Manually Approve (if needed)
------------------------------------
1. Login as Registrar
2. Go to Student Documents
3. Find the student
4. Change status to "Approved" (exact spelling!)
5. Check PHP error log for balance creation messages

STEP 4: Check if Balance Was Created
------------------------------------
Run this SQL:
SELECT * FROM student_fee_items 
WHERE id_number = '02200000001' 
AND fee_type LIKE '%Form137%';

If you see a row, balance was created!
If not, continue to Step 5.

STEP 5: Manually Create Balance (Emergency Fix)
-----------------------------------------------
If automatic creation isn't working, manually insert:

-- First, get the student's current term
SELECT school_year_term FROM student_fee_items 
WHERE id_number = '02200000001' 
ORDER BY school_year_term DESC LIMIT 1;

-- Then insert with that term
INSERT INTO student_fee_items 
(id_number, student_name, grade_level, school_year_term, fee_type, amount, paid, date_added)
VALUES

-- Verify it was created
SELECT * FROM student_fee_items 
WHERE id_number = '02200000001' 
ORDER BY date_added DESC LIMIT 1;

STEP 6: Verify in Cashier
-------------------------
1. Login as Cashier
2. Search for student: 02200000001 or "ges"
3. Should see "Document Request Fee - Form137: ₱50.00"
4. If you see it, SUCCESS!
