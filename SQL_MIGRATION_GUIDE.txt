===============================================================================
SQL MIGRATION GUIDE - Run Directly in phpMyAdmin
===============================================================================

STEP 1: MIGRATE KINDER STRUCTURE
---------------------------------

1. Open phpMyAdmin (http://localhost/phpmyadmin)
2. Select your database (probably "onecci_db" or similar)
3. Click "SQL" tab at the top
4. Open the file: migrate_kinder_direct.sql
5. Copy ALL the content
6. Paste into the SQL query box
7. Click "Go" button
8. Wait for results

WHAT IT DOES:
- Shows current Kinder records
- Creates Kinder 2 duplicates
- Renames Kinder to Kinder 1
- Shows verification results

EXPECTED RESULTS:
- "X rows inserted" (Kinder 2 created)
- "X rows affected" (Kinder renamed to Kinder 1)
- Verification table showing Kinder 1 and Kinder 2 counts


STEP 2: CLEANUP OLD SCHOOL YEARS (OPTIONAL)
--------------------------------------------

1. Still in phpMyAdmin SQL tab
2. Open the file: cleanup_school_years.sql
3. Copy ALL the content
4. Paste into the SQL query box
5. Click "Go" button
6. Review what will be deleted
7. If you want to delete:
   - Find the DELETE lines (they have -- at the start)
   - Remove the -- from each DELETE line
   - Run the script again
8. Verify deletion

WHAT IT DOES:
- Shows records that will be deleted
- Deletes 2024-2025, 2025-2026, 2026-2027 (when uncommented)
- Shows remaining records


VERIFICATION
------------

After running migrate_kinder_direct.sql, check:

1. Go to tuition_fee_structure table
2. Click "Browse" tab
3. Look for grade_level column
4. You should see:
   - Kinder 1 (multiple records)
   - Kinder 2 (multiple records)
   - NO "Kinder" records

5. Count records:
   - If you had 6 Kinder records before
   - You should have 6 Kinder 1 + 6 Kinder 2 = 12 total now


TROUBLESHOOTING
---------------

"Table doesn't exist":
- Make sure you selected the correct database
- Check table name is "tuition_fee_structure"

"Duplicate entry":
- Kinder 2 already exists, that's OK
- The script checks for duplicates

"No records affected":
- You might not have any "Kinder" records
- Check if you already have "Kinder 1" and "Kinder 2"


QUICK REFERENCE
---------------

File 1: migrate_kinder_direct.sql
Purpose: Convert Kinder to Kinder 1 & Kinder 2
Time: ~2 seconds
Safe: Yes, can run multiple times

File 2: cleanup_school_years.sql
Purpose: Delete old school years
Time: ~1 second
Safe: Yes, but requires uncommenting DELETE lines


NEXT STEPS

4. Add new school year if needed
