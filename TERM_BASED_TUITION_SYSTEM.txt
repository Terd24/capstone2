TERM-BASED TUITION FEE SYSTEM - IMPLEMENTATION COMPLETE
=======================================================

OVERVIEW:
---------
The tuition fee system now supports term-based pricing with only two terms:
- 1st Semester
- 2nd Semester

CHANGES MADE:
-------------

1. DATABASE UPDATES:
   - Added 'term' column to tuition_fee_structure table
   - Default value: '1st Semester'
   - Stores which semester the fee applies to

2. OWNER MODULE (OwnerF/):
   ✓ Simplified term filter to only show:
     - All Terms
     - 1st Semester
     - 2nd Semester
   ✓ Add Fee Modal: Added term selection dropdown
   ✓ Edit Fee Modal: Added term selection dropdown (shows current term)
   ✓ ManageTuitionFees.php: Updated to handle term field in add/update operations

3. REGISTRAR MODULE (RegistrarF/):
   ✓ add_account.php: Updated to query tuition fees by term
   ✓ When registrar selects "1st Semester", system fetches 1st Semester tuition
   ✓ When registrar selects "2nd Semester", system fetches 2nd Semester tuition
   ✓ Auto-creates student_fee_items with correct term-based amount

4. CASHIER MODULE:
   ✓ No changes needed - already displays fees from student_fee_items
   ✓ Will automatically show the correct term-based tuition fee

WORKFLOW:
---------

STEP 1: OWNER SETS TERM-BASED PRICES
-------------------------------------
Owner creates tuition fee structures for each term:

Example:
- Grade 11 STEM, 2024-2025, 1st Semester = ₱27,000
- Grade 11 STEM, 2024-2025, 2nd Semester = ₱27,000
- Grade 12 ABM, 2024-2025, 1st Semester = ₱24,000
- Grade 12 ABM, 2024-2025, 2nd Semester = ₱24,000

STEP 2: REGISTRAR ADDS STUDENT
-------------------------------
Registrar creates student account:
- Name: John Doe
- Grade Level: Grade 11
- Academic Track: STEM
- School Year: 2024-2025
- Semester: 1st Semester ← IMPORTANT!

System automatically:
1. Queries: WHERE grade_level='Grade 11' AND academic_track='STEM' 
            AND school_year='2024-2025' AND term='1st Semester'
2. Gets: ₱27,000 total fee
3. Creates: student_fee_items record with ₱27,000

STEP 3: CASHIER VIEWS BALANCE
------------------------------
Cashier searches for John Doe:
- Sees: Tuition Fee = ₱27,000 (1st Semester)
- Can record payments
- Balance updates automatically

STEP 4: NEXT SEMESTER
---------------------
When John Doe enrolls for 2nd Semester:
- Registrar creates new enrollment record
- Selects: 2nd Semester
- System fetches: ₱27,000 (2nd Semester rate)
- Creates new fee record for 2nd Semester

BENEFITS:
---------
✓ Flexible pricing per semester
✓ Owner can set different rates for each term
✓ Automatic fee assignment based on term
✓ No manual cashier entry needed
✓ Accurate term-based billing
✓ Simplified to only 2 terms (removed Summer and Whole Year)

DATABASE STRUCTURE:
-------------------

tuition_fee_structure:
- id
- grade_level (e.g., "Grade 11")
- academic_track (e.g., "STEM")
- tuition_fee (e.g., 45000.00)
- other_fees (e.g., 9000.00)
- total_fee (e.g., 54000.00)
- school_year (e.g., "2024-2025")
- term (NEW: "1st Semester" or "2nd Semester")
- created_at
- updated_at

student_fee_items:
- id
- id_number (student ID)
- school_year_term (e.g., "2024-2025 - 1st Semester")
- fee_type ("Tuition Fee")
- amount (from tuition_fee_structure.total_fee)
- paid (amount paid so far)

IMPORTANT NOTES:
----------------
1. Owner MUST create fee structures for BOTH semesters
2. If no matching term found, no fee is auto-created
3. Each semester is billed separately
4. Students can have fees for multiple semesters
5. Cashier sees all fees across all terms
